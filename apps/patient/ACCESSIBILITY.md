# 患者アプリ アクセシビリティ受入（#77）

70 代の利用を想定し、WCAG 2.2 AA を目標に以下を受入基準とする（NFR-01/02/03、docs/03 §1）。

## 受入基準

- **文字サイズ（NFR-01）**: 本文は 20sp 以上。`buildPatientTheme()` が body/title/headline の各スタイルを拡大する。OS の文字拡大（最大 200% を想定）でも内容が欠けず、スクロールで全操作に到達できる。
- **読み上げ（NFR-02）**: 画面見出しは `Semantics(header: true)`。操作要素はテキストラベルを持ち、読み上げで役割（ボタン/チェック/スイッチ）と状態が伝わる。
- **タップ領域（NFR-03）**: 主要な操作要素は 48x48 以上（iOS 44 以上も満たす）。`minimumSize: Size(48, 48)` を基本とする。
- **1 画面 1 意思決定**: 選択肢は原則 3 件。問診 Q&A は固定操作「わからない」「答えたくない」「前に戻る」「中断」を併置。
- **医療安全**: 医学的断定・未監修の安全文言を表示しない。

## 自動検証（test/a11y_acceptance_test.dart）

端末や手動操作なしに CI（patient ジョブ）で回帰確認する。各プレビュー画面に対し:

- `androidTapTargetGuideline` / `iOSTapTargetGuideline`: タップ領域の最小サイズ
- `labeledTapTargetGuideline`: 操作要素のラベル付与
- OS 文字拡大 200%・狭画面（320x640）で例外なく描画できること

対象画面: 薬剤一覧(P-020) / 薬剤候補確認(P-023) / 病院検索(P-030) / 病院詳細(P-031) /
送信前確認(P-032) / AI質問Q&A(P-013) / 問診票レビュー(P-014) / 処方箋取込(P-021) /
退会フロー(P-040/041) / アカウント(P-008) / プロフィール登録(P-006) / 通知。

## 自動検証の限界（手動確認が必要な項目）

以下は自動テストの範囲外で、実機・支援技術での受入確認が別途必要:

- 実際のスクリーンリーダー（TalkBack / VoiceOver）読み上げ順序と自然さ
- 色コントラスト比の最終確認（テーマ既定色に依存。要 AA 比測定）
- キーボード/スイッチ操作でのフォーカス順序
- 実機の OS 文字拡大・表示サイズ設定との組み合わせ

これらは #78 の E2E/実機確認、および審査前の手動受入チェックで担保する。
