# 0010. 問診AIアダプタと確定的フォールバック方針

- ステータス: 承認
- 日付: 2026-11-06
- 作成者: Devin
- 関連: 03_機能仕様書（FR-I10）, 06_医療安全_セキュリティ_運用設計書（AI-01〜AI-04）, ADR-0004

## コンテキスト

問診の追加質問生成には LLM を用いる方針（Vertex AI, API実行SAのADC/OAuth認証）
が決まっている。一方で本プロダクトは診断・処方・受診不要判断を行わず、
AI の役割は質問の順序・文言・選択肢と回答の構造化に限定される。
LLM 出力の安全性（禁止出力の非含有）と、AI不可時でも問診が成立する
確定的なフォールバックが設計上の前提となる。

## 検討した選択肢

| 選択肢 | 概要 | 利点 | 欠点・犠牲になる点 |
|---|---|---|---|
| A. LLMアダプタ＋スキーマ検証＋禁止出力フィルタ＋固定質問フォールバック（採用） | LLM生成を審査層で囲い、不合格・障害時は固定質問へ退避 | AI不可でも問診完結・禁止出力を構造的に遮断 | 実装規模が増える |
| B. LLM出力をそのまま採用 | 生成結果を直接使用 | 実装最小 | 医療安全上の禁止出力を防げない。仕様違反 |
| C. 固定質問のみ（LLM不使用） | テンプレートだけで運用 | 最も安全で単純 | 症状適応の質問最適化という要件を満たせない |

## 決定

**A** を採用する。

- `QuestionGenAdapter` インタフェースを設け、`dummy`（開発/テスト）と
  `vertex`（Vertex AI `generateContent` + `responseSchema`）を差し替え可能にする
- LLM 出力は JSON Schema で検証し、質問文・選択肢・自由記述フラグの
  構造不備は採用しない
- 診断示唆・処方/薬剤指示・「受診不要」判断に相当する禁止出力パターンで
  フィルタし、該当出力は棄却する
- いずれかの段階で不合格・タイムアウト・例外となった場合は
  **固定質問セットへ確定的にフォールバック**し、`generatedBy` に
  `fixed_template` / `llm` / `fallback` を記録する
- 患者回答は問診用AIへ渡す前に JSON へ正規化する（自由記述と選択コードを
  構造化する変換もアダプタ層の責務とする）
- `AI_INTAKE_ENABLED`（既定 false）は新規問診のAI承認値を記録するとともに、質問生成API実行時の全体停止スイッチとして評価する。実行には保存済み問診の承認と現在の全体設定の両方が必要
- 全体設定が false の場合、既存の承認済み問診もLLMを呼ばず固定質問へ退避する。問診の承認値は書き換えないため true に戻すと元の問診単位の方針が再開する
- 設定はAPIプロセスの起動時に読み込まれる。環境変数/Secret Managerの値を変えただけでは稼働プロセスへ即時反映されず、Cloud Run等の新Revisionへの切替が必要。切替後も既に開始したLLMリクエストは取り消されず、並行処理や外部送信を遡及的に停止しない
- この停止スイッチは質問生成経路に限られ、ログ・他の外部サービス・AI以外の処理を停止するものではない

## 理由

- AI が医療判断を行わないというプロダクト制約を、プロンプトではなく
  構造（検証・フィルタ・フォールバック）で保証するため
- 認証・権限の不備、障害・出力劣化のいずれでも問診フローを継続できる必要がある

## 影響

- `VERTEX_AI_MODEL` / `VERTEX_AI_LOCATION` /
  `VERTEX_AI_TIMEOUT_MS` / `AI_INTAKE_ENABLED` の環境変数を追加
- Vertex 呼び出しはサービス層の外部呼出しであり Firestore トランザクション外で実行
- 全体停止は既存問診の挙動互換性を意図的に変える。運用では承認済み設定の変更とAPI Revision/traffic切替が必要であり、適用は利用者の承認後に行う（本変更ではデプロイ・本番設定変更を行わない）

## 障害時の診断

- `AI_INTAKE_ENABLED=true` はLLM生成成功の証拠ではない。合成問診の `generatedBy` を確認し、`fallback` と `llm` を区別する。回答編集で無効化された質問も保存されるため、件数の集計では対象範囲を明記する。
- VertexがHTTPエラーを返した場合、内部のフォールバックログの `err.upstreamStatus` に上流の数値ステータスを記録する。患者向けのエラー契約は引き続き502 / `UPSTREAM_UNAVAILABLE` で、上流ステータスはAPI応答に追加しない。
- ステータスは調査の手掛かりであり、原因の確定ではない。OAuthトークン・APIキー・呼出しURL・プロンプト・モデル応答本文をログへ追加しない。

## 再評価条件

- モデル・料金・レイテンシの要件変更時
- 禁止出力ポリシーの拡充時（フィルタ規則の見直し）

## Vertex OAuth移行（2026-11-09）

- Cloud Runに紐づくAPI実行SAのApplication Default Credentialsから短命のBearerトークンを取得する。APIキー・サービスアカウント秘密鍵は不要。認証トークンはライブラリがキャッシュ・更新する。
- `AI_INTAKE_ENABLED`と問診単位の承認を維持し、EmulatorはdummyのままでADCを取得しない。本番ではAPIキーの有無でdummyへ切り替えない。認証失敗・空トークン・タイムアウトも固定質問へ安全に退避する。
- API実行SAだけに指定project内の`roles/aiplatform.user`を付与する。worker/deployerへ追加しない。モデル・地域は変更しない。404は認証、モデル名、提供地域等を個別検証する必要があり、「モデル未有効」と断定しない。
- TerraformからAPI/workerの旧キーenvとAccessorを除き、既存Secretの箱は削除しない。旧キーの無効化・削除は利用先棚卸し後の別操作とする。
- ローカルでクラウド合成試験を行う場合も対象projectを明示し、承認済みADCのみを使用する。SDK認証エラーのcause、トークン、プロンプト、応答本文をログへ渡さない。
- 参考: https://docs.cloud.google.com/docs/authentication/application-default-credentials 、https://github.com/googleapis/google-auth-library-nodejs 。
