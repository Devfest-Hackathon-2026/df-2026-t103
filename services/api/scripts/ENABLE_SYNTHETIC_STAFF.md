# 合成職員の有効化（レビュー用）

このスクリプトは合成 fixture 作成スクリプトが作成した完了台帳、施設、患者、アカウント、所属と Auth 作成時刻を検証し、該当職員だけを有効化する。実行前に独立したレビュー、明示的な実行承認、ADC の主体・権限、対象プロジェクト、施設分離、実データへの影響を確認する。実 GCP では未検証。実職員・実患者・実施設には使用しない。メールやその他の第三者通知は送らない。

MFA は強制も登録もされない。メールは未確認のままであり、有効化後はパスワード単独でアクセスできる可能性がある。ランダムで強力な相異なるパスワードを使い、安全な経路で承認された利用者にのみ渡す。終了時は担当者が正規の手段で無効化しセッションを失効する。

作成時と同じ秘密 JSON を使用し、リポジトリ外の安全なディレクトリに所有者のみ読み書き可能な 0600 の通常ファイルとして保管する。秘密は引数・ログ・チャットに記載しない。対象 project、facility、patient、staff の順と秘密ファイルのパスを CLI に渡す。コマンドは実環境専用であり、自動実行しない。

Firestore `syntheticStaffEnableOperations` に先に attempting を作成し、Auth 更新成功後に completed とする。台帳が既に存在する場合、職員が既に enabled の場合、または結果が不明な場合は自動再試行・採用・削除しない。担当者が台帳と Auth を確認し、復旧や再有効化には別途承認が必要。途中失敗時にも attempting が残る。

Firestore と Auth の間に原子性や Auth の条件付き更新はない。検査から更新までの間に別管理者が UID を削除・再作成したり fixture を変更すると誤更新の可能性があるため、操作中は対象 UID と関連文書の他の管理操作を禁止し、排他的な運用を保証できなければ実行しない。パスワードの外部変更は検出できない。患者の画面操作などで fixture 文書が変わると検査は失敗する。エミュレータ検証は実 IAM、MFA、App Check や実画面の検証ではない。
