# 架空デモ fixture（本番操作可能・個別承認必須）

**この CLI は実プロジェクトの Auth と Firestore を変更できる。本番適用は、対象・合成データ・ADC 主体/権限・分離条件を確認した独立レビューと個別の明示承認が揃った場合に限る。** この文書の承認は準備・コード統合の承認であり、実 GCP への適用承認ではない。プロジェクト ID の固定やコード上の検査は実行主体・権限を証明せず、安全性を保証しない。実患者・実職員・実施設の情報を絶対に使用しない。

明確に架空と表示した pending 施設、サーバー専用 `syntheticDemoPatients`、患者と職員のアカウント、施設所属を新規作成する。メールは予約済みの `example.test` から生成し、メール送信は行わない。メール確認は両者とも未確認、MFA は未登録。患者は `legal_pending` であり、法務同意とプロフィール登録は通常の画面・API で行う。職員は active 所属だが Auth を disabled で作成する。通常職員の実装では MFA は必須ではなく、有効化すれば未確認メール・MFA 未登録でも BFF の実 API にアクセスできるため、この fixture はログイン成功を保証しない。実在アドレスへの通知や確認済み状態の偽装はしない。

両アカウントのメールは未検証で、`example.test` では実メール確認を行えない。アプリの実メール検証、MFA、App Check、実画面 E2E、実GCP権限/分離検証は未実施。このコード変更だけでは実 GCP への適用は行わない。職員を有効化する場合は別スクリプトと別途の明示承認を要し、未検証メール・MFA 未登録のままパスワード単独でアクセス可能になるリスクがある。実職員の認証や本番利用を想定した安全な方法とは確認されていない。

実行時はリポジトリ外の現在ユーザー所有・モード 0600 の通常 JSON ファイルに、異なる強い `patient` と `staff` パスワード（16文字以上）と、独立したランダム32バイトを小文字16進64文字にした `operationKey` を格納する。最終パス要素のシンボリックリンクは拒否する。親ディレクトリも他者が変更できない安全な場所を使用する。値をログ、チャット、コマンド引数、リポジトリに書かない。同じファイルを安全に保持して再試行に使う。

ID は `synthetic-` に続く小文字英数字とハイフンのみ。既存文書・UID・メールとの衝突は上書きも採用もせず停止する。Auth と Firestore は跨いで原子的でないため途中状態が残り得る。同一 ID・同一秘密ファイルでの再実行は、台帳に確実に記録された Auth 作成と完了済み Firestore commit を検証して再開する。Auth の応答喪失や台帳記録失敗では所有権を推定せず停止する。自動削除や既存ユーザーの採用は行わない。担当者が対象プロジェクト、台帳、対象 UID、作成時刻を確認し、削除や変更が必要なら別途承認を得る。外部でのパスワード変更は検出できない。

職員有効化スクリプトは同じ `syntheticDemoOperations/{sha256(JSON.stringify(config))}` 台帳、version 1、同じ設定・秘密から計算する HMAC fingerprint、完了状態、Auth UID/email/creationTime proof、および5つの Firestore 文書の期待値を照合する。どちらかの台帳契約や fixture 内容が一致しなければ停止する。作成後の関連文書/Auth UIDに対する同時変更を防ぐ分散ロックはない。実行中は対象 UID と関連文書に対する他の管理操作を禁止し、排他を保証できない場合は実行しない。

`node --test services/api/scripts/createSyntheticDemoAccounts.test.mjs` で依存性注入テストを実行できる。CLI のテストでは SDK 初期化を注入し、環境変数と明示 target の検証後に、許可済みプロジェクト ID で初期化されることを確認する（外部サービスには接続しない）。`createSyntheticDemoAccounts.emulator.test.mjs` は別途、使い捨ての `demo-synthetic-auth` Auth/Firestore エミュレータを両方 `127.0.0.1` の隔離ポートに立てて実行する。これは Rules、実メール確認、MFA、App Check、実画面 E2E の検証ではない。

CLI 自体は実環境専用であり、エミュレータ用の CLI 実行モードはない。エミュレータテストは共通の fixture 関数を直接呼ぶため、実 CLI の ADC 権限検証にはならない。依存性注入テストは CLI の環境/target 解決と SDK 初期化引数までを確認するが、外部サービスへ接続しない。プロジェクト ID の環境変数検査は ADC の主体や権限を確認しない。使用後にメール確認や施設・所属情報を変更した場合、再実行時の整合性検査は失敗し得る。
